11 月 13 日是我读研后的第一次组会。我准备分享的是 ACL 2025 的一篇论文，叫 Task Shield。它讨论的是，Agent 一边读网页、文档和工具返回，一边决定接下来要做什么。如果读到的材料里也夹着一条指令，Agent 怎么判断自己该不该照做？[论文发表页](https://aclanthology.org/2025.acl-long.1435/)

准备的时候，我卡在了论文图 2 上。图里有一条绿色的「助手消息」，还有一条橙色的「工具返回」。我一开始以为「助手」是 Task Shield 里的另一个部件。顺着图看了一遍，又看了一个本地例子的实际输出，才搞清楚这两条消息分别是谁发出来的。

## 先看一次查日历

准备时用 Ollama 的 `qwen3.5:4b` 和一份本地示例日程跑了一次工具调用。我想知道 5 月 15 日有几个日程，分别是什么。

1. Python 把问题和日历工具的说明发给模型。模型返回一条调用请求，要求用 `get_event` 查询 `2024-05-15`。这一步产生了**助手消息**。
2. Python 取出日期参数，实际调用函数。函数读取示例日程文件，找到上午 10 点的组会和下午 3 点的实验讨论。这两条记录组成**工具结果**。
3. Python 把结果放回对话，再请求一次模型。模型根据查到的记录回答当天有两项日程，并把它们列出来。

工具的名字和参数出现在第一轮模型回复里，日程内容则是在 Python 执行查询后才进入对话。这次本地演示跑通了这段流程。Task Shield 的防御实验仍以论文作者的报告为准。[论文图 2](https://aclanthology.org/2025.acl-long.1435.pdf#page=5)

## Task Shield 在哪里检查

接着看图 2。用户只问了日程，工具返回里却多出一条发邮件的要求。用户没有交代这项工作，如果 Agent 跟着做，就把工具返回的数据当成了指令。论文把这种从外部内容进入对话的攻击称为**间接提示注入**。

Task Shield 先从用户消息里提取任务目标，例如统计日程数量、概括日程内容。后续每出现一条待检查的指令，就评估它是否对至少一个用户目标有贡献。查当天的日历有助于回答问题，顺带发邮件在这里就缺少依据。判断还要看上下文和参数，例如查询日期是否和用户问的一致。

具体实现中，检查模型给候选指令和每个用户目标之间的贡献打分。各项分数都非负，所以只要有一项为正，总分就大于零。这个规则给合理的准备步骤留出了空间。比如查日历这一步还没给出答案，但它为后面的统计提供了数据。

发现偏离后，Task Shield 会根据消息来源采取不同的处理方式。工具返回里出现偏离任务的指令时，它保留原结果，并附上反馈提醒模型。助手提出偏离任务的工具调用时，程序在执行前拦下这次调用，再让模型调整。[论文第 4 节](https://aclanthology.org/2025.acl-long.1435.pdf#page=4)

## 实验里，防御和任务完成都要看

在 AgentDojo、GPT-4o 和论文所用的 Important Instructions 攻击设置下，作者报告了四类任务的汇总结果。

| 方法 | 无攻击时的任务完成率 | 有攻击时的任务完成率 | 攻击成功率 |
| --- | ---: | ---: | ---: |
| 无防御 | 69.07% | 50.08% | 47.69% |
| Task Shield | 73.20% | 69.79% | 2.07% |

这张表里，任务完成率统计的是用户交代的事有没有做成，攻击成功率统计的是攻击者有没有达成目标。在这组实验里，加入 Task Shield 后，攻击成功率下降，受干扰时的任务完成率也提高了。[论文表 2(a)](https://aclanthology.org/2025.acl-long.1435.pdf#page=8)

论文还单独测了 Slack 任务。在 GPT-4o-mini 的这组实验里，整段对话的延迟中位数从无防御时的 6.17 秒上升到完整防御时的 62.56 秒。仅检查工具返回时是 18.78 秒。检查放在几个位置，会影响系统能拦住什么，也会影响用户要等多久。[论文表 3](https://aclanthology.org/2025.acl-long.1435.pdf#page=8) · [论文表 6](https://aclanthology.org/2025.acl-long.1435.pdf#page=14)

## 我想在组会上讲清楚的一点

每一步都和任务有关，最后也可能没做完。比如查询日历确实有帮助，可如果程序在拿到日程后报错，用户仍然收不到答案。检查模型本身也可能漏掉指令或错判贡献，导致偏离任务的动作被放行，或有用的步骤被拦下。

我现在读这篇论文，会先把模型的回复、工具的返回和程序实际执行的动作分开看。这样再看论文里的公式，就知道它约束的是哪一步。组会上我想从这个日历例子讲起。我也想知道，在同一组任务上多跑几次，检查器对同一个调用的判断会不会变。
